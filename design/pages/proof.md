# EVIDENCE & METHOD `/proof`

Rename public nav label from technical `Proof` to **Evidence** while retaining `/proof` route so current deep links continue to work. This is a judge-facing, plain-English verification view, NOT an engineer's log terminal.

## Above fold
Title `See where every conclusion came from.` Plain paragraph: dated source material → three role records → deterministic validation → locked digest → later Bitget observation. One button `Inspect a verified example` to saved investigation if available; second button `How records are verified` anchor.

## Core sections
1. `WHAT YOU CAN VERIFY` — actual source titles, publication cutoff logic, market instrument (named and type distinguished), deterministic receipt verification and supported/contested claims.
2. `FOLLOW THE RECORD` — evidence source → ATLAS → VEX → SEAL → hash → separate price reveal. Use one timeline or flow, not six cards.
3. `WHAT IS NOT PROVEN` — retrospective model may have seen outcome in pretraining, integrity hash is not an advance prediction timestamp, observed price change isn't causation/profitability.
4. `TECHNICAL APPENDIX` — collapsed by default: reproducibility steps, raw JSON download, developer repo, copyable receipt digest, test evidence *only from historical captured results*. No credentials, provider internals or engineer status in public chrome.

## Remove from public UI
`Refresh status` button, raw API statuses in global header, provider ID, quota, model pricing, deployment details, internal directory names, STATE.md, DESIGN_LEDGER.md, raw stack traces and setup instructions unless inside developer repo README. A generic "readiness" panel is not the product. If diagnostics must exist, guard or localize it for developers, not judges.

## Design
Visually consistent with the cinematic system, but deliberately calmer so evidence can be studied; dark dense table rows, timestamps in mono, small distinct cyan source markers and amber receipt. Navigation back to Chamber always present. No pretending this is a DeFi on-chain explorer: receipt is SHA-256 record integrity, not blockchain proof.
